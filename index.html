      Naming conventions

      lowercase · hyphens · fixed vocabulary · initiative-offer-period
      Parameter reference
      Source utm_sourceWho or where sent the visit: the platform, publisher or list. Examples: linkedin, google, newsletter.
      Medium utm_mediumHow it was delivered: the channel type. Examples: paid-social, cpc, email. Mediums drive channel grouping, so keep a fixed list.
      Campaign utm_campaignWhich initiative the visit belongs to, so spend, sessions and leads compare by campaign. Term (paid keyword) and content (ad or link variant) are optional detail.
      AvoidUse insteadWhy
      utm_Source=LinkedInutm_source=linkedinNames and values are case-sensitive in reports.
      utm_medium=Paid Socialutm_medium=paid-socialSpaces become %20; mixed spellings split rows.
      utm_medium=ppc / paid-searchutm_medium=cpcOne word per channel keeps reporting grouped.

      Event Tracking

      Demo-request journey from landing page to sales-accepted lead

      Reference design: no live tracking
      Campaign attribution flow: landing page to CRM
      1. Tag the link. Every ad and email link carries utm_source, utm_medium and utm_campaign (plus click IDs such as gclid where auto-tagging adds them).
      2. Capture on landing. On page load, read the parameters from the URL and keep them. GA4 reads them for reporting, but the form and CRM need their own copy.
      3. Persist across pages. Store the values in a first-party cookie or localStorage so they survive navigation from landing page to demo page. sessionStorage is lost when the tab closes and is not shared between tabs.
      4. Populate hidden form fields. Before submission, write the stored values into hidden inputs (utm_source, utm_medium, utm_campaign, landing_page, form_id).
      5. Send with the success event. Include the same values and a unique submission ID in demo_request_success so analytics and CRM can be reconciled.
      6. Map into the CRM. The form integration must map each hidden field to a CRM property. Keep first-touch and last-touch in separate properties so a later visit does not overwrite the original source.
      7. Report. Compare form events with CRM leads using the submission ID and campaign fields. Respect consent and privacy rules throughout.
      Illustrative code: capture and persist campaign parameters 
      const KEYS = ['utm_source','utm_medium','utm_campaign','utm_term','utm_content','gclid'];
const params = new URLSearchParams(location.search);
const found = {};
KEYS.forEach(k => { const v = params.get(k); if (v) found[k] = v; });

if (Object.keys(found).length) {            // only overwrite when new UTMs arrive
  found.landing_page = location.pathname;
  found.captured_at  = new Date().toISOString();
  localStorage.setItem('campaign_touch', JSON.stringify(found));
}

// before the form is submitted: copy the stored touch into hidden inputs
const touch = JSON.parse(localStorage.getItem('campaign_touch') || '{}');
Object.entries(touch).forEach(([name, value]) => {
  const input = document.querySelector('input[name="' + name + '"]');
  if (input) input.value = value;
});

      Troubleshooting

      Diagnose common tracking faults

      Suggested QA sequence for any tracking fault
      1. Reproduce with a clean browser session and a uniquely named test campaign, for example utm_campaign=qa-test-001.
      2. Check the URL after every redirect: are the UTMs still there, lowercase and correctly named?
      3. Check the tag layer in GTM Preview and GA4 DebugView: which events fire, how many times, with which parameters?
      4. Check persistence by navigating to another page and re-inspecting stored values and hidden fields.
      5. Check the network payload of the form submission for the campaign fields.
      6. Check the CRM record created by the test and compare it with what was sent.
      7. Fix one thing, retest end to end, then record the result in Tracking QA.

        Assumptions & limitations

        • All campaign figures are fictional, simulated data. This dashboard is not connected to any actual Showbay advertising, Google Analytics 4 (GA4) or CRM account, and no real clicks, leads or events are tracked.
        • Amounts are in INR. The sample has no dates, so there are no date filters or time trends.
        • "Forms" means de-duplicated successful submissions; a SAL is a lead accepted by sales.
        • The UTM Manager, filters, calculations and QA checklist are working tools. Event Tracking and Troubleshooting are reference designs, and the payloads are illustrative.
        • Each campaign has few forms and SALs, so comparisons are directional, not statistically conclusive.
        • example.com is a placeholder domain. GA4 behaviour described is general and should be confirmed in a live property.
        • Everything runs in your browser. The only external dependency is Chart.js from a CDN, so charts need an internet connection.
